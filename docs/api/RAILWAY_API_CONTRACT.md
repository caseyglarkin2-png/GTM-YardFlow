# Railway API Contract

> **Parent doc**: [.github/copilot-instructions.md](../../.github/copilot-instructions.md)

This document defines the full API contract between GTM-YardFlow (Vercel) and YardFlow-Hitlist (Railway).

## Authentication

### Service-to-Service (S2S)
All Vercel → Railway requests include:
```
x-service-key: $SERVICE_TO_SERVICE_SECRET
Authorization: Bearer $SERVICE_TO_SERVICE_SECRET
x-user-id: <firebase-uid> | service:gtm-frontend
x-request-id: <8-char-uuid>
x-source: gtm-yardflow-vercel
```

### User Context
For user-scoped operations, include:
```
x-user-id: <firebase-uid>
x-user-email: <user-email>
```

## Endpoints

### Health Check

**GET `/api/health`**

Response:
```json
{
  "status": "healthy",
  "database": "connected",
  "redis": "connected",
  "queue": { "pending": 0, "processing": 0 },
  "ai": { "openai": "connected", "anthropic": "connected" },
  "timestamp": "2026-02-05T12:00:00.000Z"
}
```

---

### Prospects

**GET `/api/prospects`**

Query params:
- `status`: `new|contacted|replied|meeting|closed`
- `tier`: `Tier 1|Tier 2|Tier 3|Tier 4`
- `search`: text search
- `limit`: number (default 50, max 100)
- `offset`: number

Response:
```json
{
  "items": [{ "id": "uuid", "email": "...", "company": "...", ... }],
  "total": 150,
  "limit": 50,
  "offset": 0
}
```

**POST `/api/prospects`**

Request:
```json
{
  "email": "required@example.com",
  "firstName": "optional",
  "lastName": "optional",
  "company": "optional",
  "title": "optional",
  "tier": "Tier 1|Tier 2|Tier 3|Tier 4"
}
```

Response: `RailwayProspect` (201 Created)

---

### Sequences

**GET `/api/sequences`**

Response: `PaginatedResponse<RailwaySequence>`

**POST `/api/sequences`**

Request:
```json
{
  "name": "required",
  "description": "optional",
  "steps": [
    { "type": "email", "subject": "...", "body": "...", "delayDays": 0 },
    { "type": "wait", "delayDays": 3 },
    { "type": "email", "subject": "...", "body": "...", "delayDays": 0 }
  ]
}
```

Response: `RailwaySequence` (201 Created)

## Error Responses

All errors return:
```json
{
  "error": "Human-readable message",
  "code": "MACHINE_READABLE_CODE",
  "detail": "Additional context",
  "requestId": "abc123"
}
```

### Status Codes

| Code | Meaning | Common Causes |
|------|---------|---------------|
| 400 | Bad Request | Missing required field, invalid email format |
| 401 | Unauthorized | Missing/invalid `x-service-key` header |
| 403 | Forbidden | Origin validation failed (CSRF) |
| 404 | Not Found | Resource doesn't exist |
| 422 | Unprocessable | Email suppressed (bounced/unsubscribed) |
| 429 | Rate Limited | 100 req/min or warmup limit (20/day) |
| 500 | Server Error | Internal Railway error |
| 503 | Unavailable | Railway down, circuit breaker open |

## Type Definitions

All types are defined in [`src/types/railway.ts`](../../src/types/railway.ts):

- `RailwayProspect` - Prospect entity with tier, status
- `RailwaySequence` - Sequence with steps array
- `RailwayEnrollment` - Prospect-Sequence relationship
- `RailwayEmail` - Email entity with tracking
- `RailwayHealthResponse` - Health check response
- `EmailTemplateRecord` - Template with variables
- `PaginatedResponse<T>` - Standard pagination wrapper

## Request Tracing

Every request includes:
1. `x-request-id` header (generated by caller)
2. Response includes `requestId` in errors
3. Railway logs correlate via this ID

For debugging production issues:
```bash
# Find request in Vercel logs
vercel logs | grep "x-request-id: abc123"

# Find in Railway logs
railway logs | grep "abc123"
```

## Circuit Breaker

The proxy (`api/railway/[...path].ts`) implements a circuit breaker:

1. **Closed**: Normal operation, requests pass through
2. **Open**: After 5 consecutive failures, requests fail immediately (503)
3. **Half-Open**: After 30s, allow one test request
4. **Closed**: On success, reset to normal

When circuit is open, callers should:
- Show "Service temporarily unavailable" message
- Queue operations for retry
- Use cached data if available
